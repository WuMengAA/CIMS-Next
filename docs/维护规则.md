## 二、铁律（违反即事故）

1. **生产服务不重启不 kill**：8090 是生产，验证一律另起隔离实例（`run-dev.bat` 或隔离端口/DB），验完只杀自己那个。
2. **不覆盖并行改动**：开工前 `git status --short` + 看目标文件 mtime；**发现 15 分钟内有人动过 → 停手**，不"我改完你再合并"。
3. **云端(8788)是 Qt 线共享物**：改 `CLOUD_WS_TOKEN` / 接入票相关，必须成对改客户端（管理端/被控端）。
4. **入口变更先报**：新路由必须排在 Cloudflare 隧道**通配规则之前**，否则被静默吞掉；用 `scripts/add-cloud-ingress.ps1`（幂等，先 `-WhatIfOnly`）。
5. **不删非本次自建的文件**：批量删前先备份 + 列清单 + 等人确认。

---

## 三、发布流程（六步）

1. **确认无并行改动**：`git status --short` + 目标文件 mtime（§2 铁律 2）。
2. **改代码**：提交信息必须含改动清单 / 行为差异 / 验证证据 / **未验证项**。
3. **本地验证**：`pnpm build` 或 `run-dev.bat` 隔离实例，跑 `verify.mjs` / `chk.mjs`（存在则用），必须全绿。
4. **生产切换**：确认 build 产物完整 → 切到 8090（用既有 `run-prod.bat` / `upgrade.ps1` / `rollback.ps1` 流程，**不自造**）。
5. **生产冒烟**：8090 首页 200；`/api/health`（若存在）正常；关键页面（登录 / 管理端控制台）可打开。
6. **回写**：指挥台「当前指针」+ git commit。

## 五、常见坑（踩过，写成规则防止再犯）

1. **路由被通配规则吞掉**：新增公网路由必须排在通配之前（§2 铁律 4）。
2. **令牌成对失效**：云端令牌改了客户端没改 → 管理端/被控端鉴权失败（AUTH_FAILED「票据签名不对」）。改一处必须成对。
3. **文件型 CMS 权限**：纯静态托管不支持后台写入，别把生产迁到纯 CDN。
4. **并行会话撞车**：2026-10-06 曾同日两会话同改 `oauth-clients.ts`（mtime 18:44 被改）——开工前 mtime 检查是成本最低的防撞手段（AGENTS.md §7.2）。
