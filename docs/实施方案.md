# 学校多媒体统一集控 · 实施方案

> 版本：v1.0（2026-09-06）
> 定位：基于 **CIMS（集控后端）+ ClassIsland（客户端）** 的学校多媒体统一集控落地方案
> 前置依据：[`CIMS_协议与代码评估报告.md`](../CIMS_协议与代码评估报告.md)（协议 100% 兼容、真实 socket 联调 5/6 通过）

---

## 0. 目标与范围

把校园里分散的多媒体设备（教室一体机、走廊大屏、会议室屏、电子班牌）统一纳管，实现：

- **统一展示**：课表、公告、倒计时、打铃、天气、值日、应急广播
- **统一管控**：远程命令（重启/刷新/锁屏）、分组批量操作、在线状态监控
- **自动隐藏**：上课/投屏/考试时段自动收起集控浮窗，不打扰教学
- **自动更新**：客户端与配置内容自动更新，无需逐台手工维护

本方案只做"集控"这一层，不替代教务、不碰云端推荐。

## 1. 技术选型结论（已验证）

| 组件 | 选型 | 理由 |
|---|---|---|
| 集控后端 | **CIMS**（Python + FastAPI + gRPC + PostgreSQL + Redis，多租户） | 协议与 ClassIsland 客户端 100% 对齐（见评估报告 2.9），代码质量认真，活跃维护 |
| 客户端 | **ClassIsland**（数字板/电子班牌软件，开源） | 原生支持视图/组件/自动化/信箱/集控协议 |
| 硬件 | 教室 Windows 一体机 / 安卓盒子 / 电视棒 | 跑 ClassIsland 即可，校园网互通 |

**排除项**：官方集控（冻结）、自研（性价比低）。详见评估报告第 4 节。

## 2. 整体架构

```
                        校园网 (固定域名 cims.example.edu / 内网 IP)
                                   │
        ┌──────────────────────────┼──────────────────────────┐
        │                  CIMS 集控服务器 (Docker)            │
        │  ┌────────────┐  ┌──────────────┐  ┌────────────┐  │
        │  │ Client API │  │ Management   │  │   Admin    │  │
        │  │  :client   │  │ API :mgmt    │  │  API :admin│  │
        │  │(终端连接/   │  │(账户/用户/   │  │(超管/2FA/  │  │
        │  │ manifest)  │  │ 邀请/配对)   │  │ OOBE)      │  │
        │  └─────┬──────┘  └──────┬───────┘  └─────┬──────┘  │
        │        │  gRPC :27044   │  PostgreSQL 18 │ Redis 7  │
        └────────┼────────────────┼────────────────┼──────────┘
                 │ (Cyrene_MSP gRPC)
                 │
   ┌─────────────┼─────────────────────────────────────┐
   │  每台多媒体设备（ClassIsland 常驻）                  │
   │  · 视图(课表/公告/倒计时/打铃/天气/值日)            │
   │  · 自动化规则（条件→切换视图/隐藏）                 │
   │  · 信箱/集控（拉取配置、收命令、收通知）            │
   │  · 内网更新源（自动更新客户端）                     │
   └────────────────────────────────────────────────────┘
```

**数据流**：CIMS 存配置/课表/公告 → 客户端定时拉取 Manifest（`/api/v1/client/{uid}/manifest`）→ 本地渲染。
**命令流**：CIMS → gRPC command（重启/通知/状态）→ 客户端执行（实时命令当前走 gRPC，详见 §7 约束）。

## 3. CIMS 部署（Docker 一键）

提供 `deploy/` 目录：`docker-compose.yml`（FastAPI + PostgreSQL 18 + Redis 7 + 反向代理）、`.env.example`、一键脚本。
要点：

- 三端口隔离：client / management / admin（生产建议仅暴露 management + 反代 client）
- HTTPS：反代层终止 TLS，内网可自签或校 CA
- PGP 密钥：OOBE 初始化时生成，用于握手挑战
- 持久化：PostgreSQL 卷 + Redis（会话/心跳）

详见 [`deploy/README.md`](../../deploy/README.md)。

## 4. ClassIsland 客户端部署与功能映射

| 集控功能 | ClassIsland 实现 |
|---|---|
| 课表展示 | 课表组件（数据经 CIMS Manifest 下发） |
| 倒计时 / 打铃 | 倒计时组件 + 打铃配置 |
| 公告 / 通知 | 信箱 + 通知组件（CIMS 下发 `SendNotification` 或信箱） |
| 天气 / 值日 | 原生组件 |
| 应急广播 / 紧急通知 | CIMS 下发紧急通知 / 切换应急视图 |
| 远程命令 | CIMS command（重启/刷新/锁屏），实时走 gRPC |
| 分组批量 | CIMS 按教学楼/教室分组，批量下发 |

客户端安装：每台设备装 ClassIsland，配置指向 CIMS 地址（client 端口 + 域名），启动即注册握手。

### 4.1 电教委员操作面板（独立客户端）

面向**电教委员**的独立集控客户端（Tauri 2 壳 + 零框架前端，快且占用少）：

- 课表 / ClassIsland 配置 / 插件**远程改并下发**到本班设备
- 设备远程控制：重启、强制同步配置、下发通知（直接走 CIMS management 端口 `/account/{acct}/client/{uid}/command/*`）；锁屏/截图 CIMS 无原生接口，列为后续扩展
- 通知广播（本班/年级/全校）、**班级间快捷交流**
- **故障上报**工单、**Bug 提交**（含复现步骤与日志）、操作日志审计
- API 友好：统一 API 层，后端地址/令牌可配，无后端自动降级演示数据

详见 [`admin-console/README.md`](../admin-console/README.md)，后端契约见 [`admin-console/API.md`](../admin-console/API.md)。

## 5. 自动隐藏实现

目标：集控浮窗在不需要时自动收起，不挡投影/上课内容。

**三层实现**：

1. **ClassIsland 自动化（Automation）** —— 主手段
   - 触发器：时间/课程状态/网络条件
   - 动作：切换"主视图"↔"专注/隐藏视图"
   - 示例：上课时段自动隐藏主浮窗；投影模式（检测到全屏应用）自动收起
   - 配置模板见 [`classisland-config/自动化规则-上课自动隐藏.json`](../../classisland-config/)
2. **常驻托盘**：客户端最小化到系统托盘运行，仅留必要浮窗，需要时弹出。
3. **集控触发**：CIMS 下发命令 / `DataUpdated` 事件，让指定分组统一切换视图或隐藏（如考试时段全校隐藏娱乐组件）。

## 6. 自动更新实现

| 更新对象 | 机制 |
|---|---|
| 客户端本体 | ClassIsland 内置更新器，更新通道指向**内网更新源**（不依赖公网 GitHub，合规） |
| 配置 / 内容 | CIMS 定时或被动下发（`ConfigUpload` / `DataUpdated` 触发客户端重新拉取 Manifest），无需人工逐台改 |
| 批量运维 | CIMS 对所有在线客户端批量下发 `RestartApp` / 更新指令 |

内网更新源搭建说明见 [`classisland-config/内网更新源说明.md`](../../classisland-config/)。

## 7. 已知约束与对策（务必正视）

| 约束 | 现状 | 对策 |
|---|---|---|
| **bidi 命令流在 grpcio 1.78 真实 socket 下有边界 bug** | 真实 socket 联调 ListenCommand 失败（服务端 peer `async_generator can't be used in 'await'`），in-process 24/24 全过 | MVP 阶段用**客户端定时拉取 Manifest** 模式（ClassIsland 默认即拉取式），覆盖配置/公告/课表自动更新；实时命令待降级 grpcio 或 CIMS 修复 bidi 后启用 |
| **客户端实时控制已通过 management 端口 HTTP 暴露** | `/account/{acct}/client/{uid}/command/*`（restart/update-data/send-notification/status） | 面板直接调用，无需自建命令网关；bidi 流 bug 不影响单向推送命令 |
| **CIMS 无独立 WebUI** | 管理走 API / OOBE / 脚本 | 本方案提供 `admin-frontend/` 最小管理前端原型，对接 management API |
| **运维代价（PostgreSQL+Redis）** | 较官方 MySQL 方案重 | `deploy/` Docker Compose 封装，一键起停 |

> 协议正确性不受影响：评估报告 §2.10 已实锤 CIMS 协议实现正确，上述均为运行/工程层约束，非协议缺陷。

## 8. 分阶段路线图

- **MVP（1–2 周）**
  - CIMS Docker 部署 + 域名/HTTPS/PGP
  - 每台设备安装 ClassIsland，指向 CIMS
  - 课表/公告展示 + 配置自动下发（Manifest 拉取模式）
  - 管理前端：账户/分组/用户管理（management API）
- **进阶（2–4 周）**
  - 自动化隐藏规则全量配置（上课/考试/投影）
  - 内网更新源 + 客户端自动更新
  - 管理前端补全：客户端列表/在线状态/邀请/配对
- **实时命令（依赖 grpcio 修复或降级）**
  - 启用 bidi 流：即时紧急通知、远程重启/锁屏
  - 或自建 HTTP→gRPC 命令代理
