1 · 五分钟部署

唯一的前提 整个目录一起拷到教室电脑，不能只拷 app 或只拷 scripts。 脚本按相对路径找同级文件，缺一个目录就装不起来。
  1. 拷包
    把整个部署包目录（约 330 MB）拷到教室电脑，例如 C:\Users\Public\Desktop\ClassroomDeploy。
  2. 填服务端地址
    打开 config\deployment.json，把 "ServerBase" 改成学校服务端地址（形如 http://10.0.0.10:8096）。
    不想改文件也行 —— 下一步会问你。其余字段留空即可，脚本会自动补。
  3. 双击 1-部署到本机.cmd
    弹出 UAC 时点「是」。脚本会走七步：读配置 → 检查环境 → 装本体 → 铺数据 → 写配置 → 建自启和快捷方式 → 自检。
    连不上服务端只会警告、不会中断 —— 教室断网也要能显示课表。
  4. 启动一次
    双击桌面上新出现的「ClassIsland」。主界面应显示课表。 此时还没连服务端也正常，包里带了一份离线档案。
  5. 在面板里给这台设备登记班级
    双击桌面「电教委员面板」→ 在设备页把这台机器的标识绑定到对应班级。 绑定后服务端会下发该班课表，教室端自动切换。

想确认整体状态，双击 2-环境自检.cmd。全绿即成功。

3 · 一个必须理解的事实

用浏览器打开 http://<服务端>:8096/… 会返回 403 —— 这不是故障 服务端靠 HTTP 请求里的 Host 头识别「这是哪个班」，而浏览器不会替你设置它。 教室端插件会主动设置这个头，所以插件工作正常。 实测同一接口：带 Host: demo-class.localhost 返回 200，裸 IP 返回 403。

由此推出两条实用结论：

  • 填 IP 就行，不必让它看起来像域名。租户身份由配置里的 Slug + BaseDomain 决定， 与地址栏里的主机名无关。
  • 排错时不要用浏览器测 8096。用 2-环境自检.cmd，它按插件的方式带 Host 头请求， 结果才有意义。

5 · 出问题了怎么办

  1. 双击 2-环境自检.cmd，看有没有红项。
  2. 想发报告：2-环境自检.cmd -Report check.txt，把生成的 txt 发给管理员。 报告已脱敏，不含密钥。
  3. 还在上课时间、需要立刻恢复：4-回滚.cmd -Last，一分钟内退回上一个可用版本。 先恢复可用性，再查根因。

最常见的三种情况：

现象多半是怎么修

自检说 Manifest 403Slug 或 BaseDomain 与服务端不一致核对服务端 .env 的 CIMS_BASE_DOMAIN 与账户 slug
主界面没课表设备还没在面板绑定班级去面板绑定；或先看自检是否通过

6 · 换版本（升级 / 降级）

换版本前请先知道：日常只需要换插件（约 500 KB），不必动 281 MB 的本体。 脚本会自动先停 ClassIsland —— 因为宿主会锁住插件 DLL，运行中替换必然失败。 
REM 只升级插件（最常见）
3-升级或降级.cmd -From E:\ClassroomDeploy-新版本

REM 连 ClassIsland 本体一起升级
3-升级或降级.cmd -From E:\ClassroomDeploy-新版本 -WithApp

REM 降级 —— 把 -From 指向旧版本包即可，不需要别的参数
3-升级或降级.cmd -From E:\ClassroomDeploy-旧版本

REM 回滚到最近一次替换前的状态
4-回滚.cmd -Last

REM 只是服务端地址被改乱了
4-回滚.cmd -RestoreSyncOnly

升级/回滚每次都会自动备份旧文件到 插件目录\.bak-<时间戳>\，所以「回滚错了想切回来」也是可以的。

怎么确认新版本真的生效了（两个硬判据） ① 进程启动时间晚于 DLL 修改时间（自检里已做成检查项）—— 进程更早就说明跑的还是内存里的旧代码；
② 出现了本轮新增的 ste-*.log —— 新代码路径启动时才会创建。 面板里的版本号读的是 manifest.yml，它只能证明清单换成功了，不能证明 DLL 换了。

7 · 服务端在哪里

整套系统对外只有两个地址，教室端也只填这两个：

名称形态谁需要访问
CIMS 地址http://<主机>:8096所有教室端（★必须放行）
面板地址http://<主机>:8090/admin/console电教委员 / 管理员（浏览器）

服务端放哪里不重要，重要的是这两个地址从教室网络能通。三种选择：

  • 校内一台常开机器（推荐） —— 延迟低、不依赖外网、数据在校内。
  • 装在某一间教室的电脑上 —— 只适合一两个班；这台机器一关，其他班也失去集控。
  • 公网（多校共用，可带容灾） —— 走 Cloudflare Tunnel：不需要公网 IP、不需要自己申请证书、 不需要开放任何入站端口，源站只监听 127.0.0.1。此时地址改成租户自己的子域名 （https://<slug>.<基域>），并用泛域名一条规则覆盖所有租户。 详见 docs\07-公网接入与容灾双实例.md。
公网部署有两个必须确认的点 ① 服务端 .env 里的 CIMS_TRUSTED_PROXIES 必须配上（cloudflared 在本机则填 127.0.0.1），否则限流中间件会把全网设备看成同一个 IP —— 任意一个人打满阈值，全校设备一起被封 60 秒。 ② 数据库不能和主实例装在同一个台机器上，否则「主机挂了切备用」是假容灾。
服务端不可用时会怎样（有意的降级设计） 课表显示、上课提醒这些核心功能完全在本地，断网不影响上课。 断网期间：课表停在最后一次同步成功的版本、收不到新广播、面板上这台设备显示为离线。 网络恢复后插件自动继续同步 —— 它只是这一轮没拉到，不会退出、也不会被禁用。

8 · 官方集控功能（ClassIsland 自带）

ClassIsland 自带一套集控功能，和本项目自研的星璃集控不是一回事，但用的是同一套数据格式。

官方集控星璃集控（本项目）
怎么开设置 → 集控 → 加入集控装插件 + 填 stelarith-sync.json
权限保护有：禁改设置/课表、禁退出、凭据校验无（依赖宿主权限体系）
设备状态上报无有
命令通道官方服务端模式（官方标注「开发中」）HTTP 轮询，可用
服务端状态静态配置模式可用已可用

绑定设置怎么写

在 ClassIsland 安装目录建 ManagementPreset.json：

{
  "ManagementServerKind": 0,
  "ManagementServer": "",
  "ManifestUrlTemplate": "https://example.com/manifest.json",
  "ClassIdentity": "1-201"
}

ManagementServerKind：0 = 静态托管的配置文件（可用）； 1 = 集控服务器（官方标注「正在开发」）。URL 模板只支持两个占位符： {id}（客户端 ID）和 {cuid}（唯一客户端 GUID）。

两套机制并存时最容易踩的坑：档案双写 官方集控和星璃插件都会往同一份课表档案里写， 结果课表在两个版本之间来回跳，表现为「课表偶尔变回旧的」。
规则是二选一：用官方集控下发课表 → 把 ResourceWriteBack 设为 false； 用星璃插件下发 → 不要启用官方集控。 关掉写回后，星璃插件仍可正常工作（上报状态、收广播、点歌上屏），只是不再碰课表档案。

完整说明（含官方 URL 模板、策略与凭据的完整字段表、与 CIMS 对接的前提）： docs\03-官方集控与绑定设置.md

9 · 常用速查

场景命令
首次部署1-部署到本机.cmd
无人值守部署（配置已填好）deploy.ps1 -NonInteractive
只看计划不动磁盘deploy.ps1 -DryRun
自检并存报告2-环境自检.cmd -Report check.txt
只升插件upgrade.ps1 -From E:\包 -WithApp（去掉 -WithApp 即只升插件）
回滚rollback.ps1 -Last

这台机器也当服务端deploy.ps1 -OpenFirewall

数据与目录（装完之后的分布）

C:\ClassIsland\
├── ClassIsland.exe              ← 启动器（快捷方式指向它）
├── app-2.1.0.1-0\               ← 程序本体（ste-*.log 插件日志在这里）
├── assets\musics\               ← 提醒音效
└── data\
    ├── Settings.json            ← 宿主设置（含安装路径绝对路径）
    ├── Profiles\Default.json    ← 课表档案
    ├── Config\                  ← 各插件设置
    └── Plugins\
        └── StelarithControlPlugin\
            ├── StelarithControlPlugin.dll / deps.json / manifest.yml
            ├── stelarith-sync.json    ← ★服务端地址在这里
            └── stelarith-panel.json
分发前请自查（安全） 不要把带真密钥的配置打进去。已知风险点：第三方 AI 插件的 aisettings.json 里有明文 apiKey；stelarith-sync.json 的 VoiceHubKey； 以及任何 .env / 启动脚本。 出包脚本已内置排除与脱敏，但如果你是手工拷目录，请自己对照检查。
