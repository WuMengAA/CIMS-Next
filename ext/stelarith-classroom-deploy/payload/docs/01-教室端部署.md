# 01 · 教室端部署

> 面向：到教室里动手装的人（电教委员 / 运维）。
> 目标：一台教室电脑，开机自动显示本班课表，并能接收集控广播与点歌上屏。

---

## 0. 先理解一件事：教室端能不能连上服务端，与域名无关

这是整套方案里最容易被误解、也最容易排错踩空的一点。

CIMS 服务端靠 **HTTP 请求里的 `Host` 头** 来识别「这是哪个学校/哪个班」。
星璃集控插件在发请求时会**主动把这个头设成 `<slug>.<基域>`**（例如 `demo-class.localhost`），
所以教室端只要：

- 能 TCP 连上服务端的 8096 端口；
- 插件配置里的 `Slug` 与 `BaseDomain` 和服务端一致；

就够了。**不需要 DNS、不需要内网域名、不需要 host 文件。**

> **如果是公网部署**（服务端在互联网上、多校共用），这一条要反过来：那时服务端的
> `CIMS_BASE_DOMAIN` 是一个真实域名，教室端就必须填域名，且基域要与服务端一致。
> 见 `docs/07-公网接入与容灾双实例.md`。判据只有一条：**插件配的 `BaseDomain`
> 必须等于服务端 `.env` 里的 `CIMS_BASE_DOMAIN`**。

实测（服务端本机，同一份 Manifest 接口）：

| 请求方式 | 结果 |
|---|---|
| 带 `Host: demo-class.localhost` | **200** |
| 裸 IP 直连（不带自定义 Host） | **403**（`code=100403 未识别出租户`） |

> 这条也解释了一个常见困惑：**用浏览器直接打开 `http://<服务器IP>:8096/...` 会是 403，但教室端插件工作正常**。不是服务端坏了，是浏览器不会替你设置那个 Host 头。

## 1. 三种交付方式，按教室条件选

### 方式 A · U 盘离线拷贝（推荐，教室无外网时唯一可行）

1. 把整个部署包目录拷到 U 盘（约 **330 MB**）。
2. 到教室，把整个目录拷到教室电脑（例如 `C:\Users\Public\Desktop\ClassroomDeploy`）。
   **必须整个目录一起拷**，不能只拷 `app` 或只拷 `scripts`——脚本按相对路径找同级文件。
3. 双击 `1-部署到本机.cmd`（会弹 UAC，点「是」）。

### 方式 B · 局域网共享 / 网络拷贝

在服务端把部署包共享出来（只读即可），教室端：

```cmd
robocopy "\\<服务端IP>\deploy\ClassroomDeploy" "C:\ClassroomDeploy" /E
cd /d C:\ClassroomDeploy
1-部署到本机.cmd
```

> 注意：**课表同步走 8096，与文件共享是两条路**。文件共享只是把安装包送过去，
> 装完之后日常同步不需要共享一直开着。

### 方式 C · 远程推送（教室电脑已开机、且能远程管理时）

前提：目标机开了 `WinRM` 或 `SMB`，且你有管理员凭据。

```powershell
# C-1 用 SMB 送包（最简单）
robocopy "\\<源>\ClassroomDeploy" "\\<教室机>\C$\ClassroomDeploy" /E

# C-2 用 WinRM 远程执行
$s = New-PSSession -ComputerName <教室机> -Credential (Get-Credential)
Invoke-Command -Session $s -ScriptBlock {
    powershell -ExecutionPolicy Bypass -File C:\ClassroomDeploy\scripts\deploy.ps1 -NonInteractive
}
```

`-NonInteractive` 表示「配置全部取自 `config\deployment.json`，不要问我」——
远程无人值守时必须加分项。所以远程前**先把 `deployment.json` 填好**。

### 方式 D · 批量（同型号教室机多台）

先在一台机器上完整装好并确认可用，然后：

- 用系统自带的**磁盘克隆/镜像**工具把该机器做成母盘；
- 或把 `C:\ClassIsland` 整个目录（含 `data`）打包，逐台释放。

逐台释放时，**每台的 `ClientUid` 必须不同**（否则服务端会把两台当成一台，互相覆盖状态）。
释放后执行一次：

```powershell
# 只重写身份相关的配置，其余保留
powershell -ExecutionPolicy Bypass -File scripts\deploy.ps1 -NonInteractive
```

并在 `deployment.json` 里把 `ClientUid` 留空 —— 留空时脚本会自动取**计算机名**（小写化），天然唯一。

## 2. 部署前需要准备的东西

| 项 | 从哪来 | 说明 |
|---|---|---|
| 服务端地址 | 服务端管理员 | 形如 `http://10.0.0.10:8096`，**不要带结尾斜杠** |
| 租户 Slug | 服务端管理员 | 星璃演示环境是 `demo-class` |
| 租户基域 | 服务端管理员 | 等于服务端 `.env` 的 `CIMS_BASE_DOMAIN`，默认 `localhost` |
| 本机设备标识 | 自己定 | 建议 `class201-pc` 这类；留空自动用计算机名 |
| 班级课表名 | 面板里查 | 形如 `cp_class02`；**也可以留空**，等面板里给设备绑定班级后自动生效 |

这些填到 `config\deployment.json` 里，或者部署时按提示输入。

## 3. 部署脚本实际做了什么（七步）

| 步骤 | 动作 | 会不会动系统 |
|---|---|---|
| 1 | 读取并校验配置，缺项就问你 | 否 |
| 2 | 前置检查：源文件完整、磁盘 ≥2GB、系统版本、服务端连通性 | 否 |
| 3 | 复制 ClassIsland 本体到 `C:\ClassIsland` | 只写自己的目录 |
| 4 | 铺开预置数据；**已存在的文件一律不覆盖** | 只写自己的目录 |
| 5 | 写 `stelarith-sync.json`（指向服务端）、`stelarith-panel.json`（面板地址）；修正宿主 `Settings.json` | 写自己的目录 |
| 6 | 加入开机自启、建桌面快捷方式 | 当前用户的「启动」文件夹 + 桌面 |
| 7 | 自检 9 项并打印结果 | 否 |

**它不做的事**（有意为之）：不改注册表、不改系统服务、不装 .NET 运行时、不动防火墙、
不做静默安装、不联网下载任何东西。

### 为什么第 3 步是复制而不是「安装」

ClassIsland 的目录版是**绿色便携**形态：`ClassIsland.exe` 是启动器，
真正的程序在 `app-2.1.0.1-0\` 里，数据在 `data\` 里。整个目录复制过去就能跑，
不需要安装程序，也不需要提前装 .NET 运行时（包内自带）。

### 为什么第 5 步要改 `Settings.json` 的一个开关

有且只有一处必要的宿主设置修改：把 `AutoDisableCorruptPlugins` 置为 `false`。

原因：ClassIsland 2.1 对第三方插件**没有运行时的启用/禁用接口**，但有一条启动期逻辑——
当 `AutoDisableCorruptPlugins = true` 时，任何在加载阶段抛异常的插件会被**自动禁用**。
教室里其他插件偶发抽风，就可能把集控插件连带禁用，结果是**教室端静默失联、且没有任何告警**。
所以必须关掉它。插件自身（`StelarithHostGuard`）在启动时也会做同样的事，双重保险。

脚本改这个文件是**逐键替换式**修改（不是整体重写），改前自动备份为 `Settings.json.before-deploy-<时间戳>`。

## 4. 部署后必须做的三件事

### 4.1 启动一次，确认课表出现

双击桌面「ClassIsland」。主界面应显示预置的课表。
此时**还没连服务端也是正常的**，因为包内带了一份离线档案。

### 4.2 在集控面板里给这台设备登记班级

打开桌面上的「电教委员面板」快捷方式（或浏览器访问 `http://<服务端>:8090/admin/console`），
进入设备/班级相关页面，把设备标识 `class201-pc` 绑定到对应班级。
绑定后，服务端下发该班的课表，教室端会自动切换。

> 为什么需要这一步：服务端存的 `ClientUid` 只负责「这台机器是谁」，
> 「这台机器该上哪个班的课表」是另一层映射，由面板维护。

### 4.3 跑自检

双击 `2-环境自检.cmd`。全绿即部署成功。
有黄/红项时，把整页内容复制下来发给服务端管理员。

## 5. 部署成功的判定标准（客观、可复现）

| 检查项 | 怎么看 | 期望 |
|---|---|---|
| 本体就位 | `C:\ClassIsland\ClassIsland.exe` 存在 | 存在 |
| 版本目录 | `C:\ClassIsland\app-2.1.0.1-0\` | 存在 |
| 插件就位 | `…\data\Plugins\StelarithControlPlugin\` 下 6 个文件 | dll / deps.json / pdb / manifest.yml / icon.png / stelarith-sync.json |
| 同步配置 | `stelarith-sync.json` 的 `ClientAppBase` | 等于你的服务端地址 |
| 服务端认得出 | 自检里 `Manifest 接口` | `HTTP 200` |
| 插件真在跑 | `C:\ClassIsland\app-2.1.0.1-0\ste-*.log` | 文件在，且最后写入在 15 分钟内 |
| 面板能看到 | 面板设备列表 | 本机在线、显示插件版本 |

## 6. 目录结构

```
ClassroomDeploy\
├── 1-部署到本机.cmd          ← 双击开始（自动提权）
├── 2-环境自检.cmd            ← 出问题先跑这个
├── 3-升级或降级.cmd          ← 换版本
├── 4-回滚.cmd                ← 退回上一个可用状态
├── config\
│   └── deployment.json       ← ★所有可变配置都在这里
├── app\                      ← ClassIsland 本体（便携，含自带运行时）
├── seed\data\                ← 预置数据：档案 / 设置 / 全部插件（已脱敏）
├── scripts\                  ← 部署、自检、升级、回滚脚本
└── docs\                     ← 你正在看的这些文档
```

`config\deployment.json` 是唯一需要改的文件。它带完整的字段说明（`_字段说明` 段）。
