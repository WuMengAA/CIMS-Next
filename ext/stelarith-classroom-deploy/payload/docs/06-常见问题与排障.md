# 06 · 常见问题与排障

> 遇到问题先跑 `2-环境自检.cmd`，它覆盖了下面 80% 的情况。
> 这份文档解释「为什么」以及「怎么修」。

---

## A. 部署阶段

### A1. 双击 `1-部署到本机.cmd` 一闪而过

多半是**没以管理员身份运行**。脚本需要写 `C:\ClassIsland`、启动文件夹和桌面。
`1-部署到本机.cmd` 会尝试自动提权；如果你的策略禁止脚本提权，就手动来：
右键 →「以管理员身份运行」。

### A2. 提示「部署包缺少 app 目录」

只拷了一部分文件。**整个目录一起拷**（`app` / `seed` / `scripts` / `config` / `docs` 五个都在）。

### A3. 提示「连不上服务端」但仍继续

这是**正常的降级行为**，不是失败。ClassIsland 会先按包内预置档案显示课表。
网络通了插件会自动开始同步。

但请顺手确认一下：服务端的 8096 端口是不是真的开着（从**另一台**机器测）。

### A4. 第一次启动弹出欢迎向导

说明预置数据没生效（`seed\data\Settings.json` 里 `IsWelcomeWindowShowed` 应为 `true`）。
跟着向导走完也能用，但档案会是空的 —— 走完再跑一次部署脚本即可补齐。

---

## B. 教室端显示相关

### B1. 主界面没有课表 / 课表是空的

按顺序查：

1. 面板里这台设备**绑定班级了吗**？未绑定时服务端只会下发默认资源。
2. 面板里看不到这台设备 → 看自检的「Manifest 接口」项。
3. Manifest 正常但仍无课表 → 看插件日志 `ste-*.log` 里有没有同步错误。

### B2. 课表一直不更新

| 可能原因 | 怎么确认 |
|---|---|
| 服务端没改 | 面板里的课表是不是新的 |
| 版本号没变 | 服务端的资源版本号只有在资源真的变化时才递增；若你直接改库绕过了版本更新，客户端不会重拉 |
| `sync` 模块被关了 | 面板 ClassIsland 专页看模块开关 |
| `writeback` 被关了 | 同步到了但没写进宿主档案 —— 这是**有意**的设计，此时面板会显示同步成功但大屏不变 |

### B3. 课表在两个版本之间来回跳

**档案被两边同时写**。典型场景：官方集控和星璃插件都启用了，且
`ResourceWriteBack = true`。

解决：二选一 —— 要么关掉官方集控，要么把 `ResourceWriteBack` 设为 `false`。
详见 `03-官方集控与绑定设置.md` 第 5 节。

### B4. 广播不显示 / 来源名不对

- 不显示：面板里该设备的 `notification` 模块是否开启；
- 来源名：改 `stelarith-sync.json` 的 `NotificationSourceName`（默认「集控广播」），重启生效；
- **务必看「送达数」而不是 HTTP 状态码**：广播是 fail-open 设计，
  CIMS 不可达时它只记 `delivered: 0` 并返回 200，看起来像「成功」。
  面板里 `delivered / total` 才是真相。

### B5. 上岛组件（正在播放 / 点歌名单 / 集控状态）不显示

- 「点歌名单 / 正在播放」需要**配置点歌站**：在 `stelarith-sync.json` 填
  `VoiceHubBase`（+ `VoiceHubKey`）。两项都不填时组件显示「未配置点歌站」，这是正常状态。
- 组件**前景色继承主题**（不写死白色）。浅色主题下如果看到白字不可读，那是主题配置问题，不是组件 bug。

### B6. 插件设置页字体看不清

已修。规则是：**插件页一律取宿主的动态画刷，不硬编码颜色**。
教室屏幕亮/暗主题都有，写死白字在浅色主题下直接不可读。
如果你看到其它插件页有这个问题，那是那个插件的问题。

## C. 连接与网络

### C1. 用浏览器访问 `http://<服务端>:8096/...` 是 403

**这不是故障。** CIMS 的租户识别依赖 `Host: <slug>.<基域>` 这个请求头，
浏览器不会替你设置它。教室端插件会主动设置，所以插件工作正常。

想用浏览器验证，就要自己带头：

```bash
curl -i -H "Host: demo-class.localhost" "http://10.0.0.10:8096/api/v1/client/class201-pc/manifest"
```

### C2. 自检显示「Manifest 接口 403」

服务端在，但租户没匹配上。逐项核对：

| 项 | 在哪看 | 应该 |
|---|---|---|
| 插件配置的 `Slug` | `stelarith-sync.json` | 等于服务端 CIMS 的账户 slug（演示环境 `demo-class`） |
| 插件配置的 `BaseDomain` | 同上 | 等于服务端 `.env` 的 `CIMS_BASE_DOMAIN`（默认 `localhost`） |
| 服务端账户是否存在 | 服务端 `/account/list` | 至少有一个账户 |

### C3. 自检显示「Manifest 接口 404」

路径到了但设备没登记。在面板里把这台设备的 `ClientUid` 建出来/绑定班级即可。

### C4. TCP 端口不通

在**另一台**机器上测（本机测不出防火墙问题）：

```powershell
Test-NetConnection -ComputerName 10.0.0.10 -Port 8096
```

不通就查服务端防火墙是否放行 8096。**默认是不放行的** ——
Windows 防火墙只会为「有显式规则的程序」放行，光有服务在监听没用。

## D. 性能与体积

### D1. 插件日志文件越来越大

`app-<版本>\` 下的 `ste-*.log` 会持续增长（实测其中一个轮询日志到过 1.3 MB）。
目前**没有自动轮转**。手工清理：

```powershell
# 看体积
Get-ChildItem "C:\ClassIsland\app-*\ste-*.log" | Select-Object Name, @{n='KB';e={[math]::Round($_.Length/1KB,1)}}
# 清空（保留文件，避免插件句柄失效）
Get-ChildItem "C:\ClassIsland\app-*\ste-*.log" | ForEach-Object { Clear-Content $_.FullName }
```

建议：把它加进每月巡检。注意要**清空而不是删除** —— 插件以追加方式持有文件句柄。

### D2. 磁盘占用

| 项 | 约 |
|---|---|
| ClassIsland 本体 | 280 MB |
| 预置数据（含全部插件） | 25 MB |
| 长期增长 | 日志 + `data\Backups\` |

建议每台预留 **2 GB** 以上。

### D3. 内存

ClassIsland 常驻内存通常在 200–400 MB。教室电脑建议 4 GB 以上。

## E. 安全

### E1. 部署包里不能带的东西（做包时务必检查）

**真实事故**：本机 ClassIsland 的
`data\Config\Plugins\ClassIsland.AISmartClass\aisettings.json` 里存着一条明文
`apiKey`。这种配置一旦被打进分发包，就等于把密钥发给了全校。

打部署包时必须排除/脱敏：

- 任何 `aisettings.json` 之类的**第三方插件配置**中的密钥字段；
- `stelarith-sync.json` 里的 `VoiceHubKey`（要用就现场填）；
- `.env` / 启动脚本（历史上有过明文凭据随公开仓库泄漏）；
- 日志文件（可能含 IP、路径、请求内容）。

本项目的出包脚本已内置这些排除规则（见 `build-package.ps1`），
但**如果你是手工拷目录**，请自己对照这份清单。

### E2. 集控面板的账号

- 面板是 Web 应用，权限判断全在服务端。不要试图靠前端隐藏按钮来限制权限。
- 面板的密码/凭据不要写在启动脚本里，放未入库的 `.env`。
- 远程控制权限只给必须的人。

### E3. 教室端的物理安全

- 教室电脑如果允许学生操作，「防乱动」应该用 **ClassIsland 官方集控的策略+凭据**
  （见 `03-官方集控与绑定设置.md`），而不是靠藏窗口。
- 部署脚本创建的桌面快捷方式可以被删掉；真需要防删，用系统层面的策略。

## F. 诊断信息收集（发回给管理员时）

一条命令生成可发送的报告：

```cmd
2-环境自检.cmd -Report check.txt
```

报告会自动包含系统、安装完整性、进程、服务端连通性、插件日志摘要。
生成在脚本同目录下。

**不要**直接发送整个 `stelarith-sync.json` 或 `.env` —— 里面可能有密钥。
自检报告已经脱敏（只显示地址与标识，不显示 `VoiceHubKey`）。

## G. 仍然解决不了

按这个顺序收集信息，基本能一次定位：

1. `2-环境自检.cmd -Report check.txt` 的输出；
2. `app-<版本>\` 下所有 `ste-*.log` 的**最后 30 行**；
3. `data\Settings.json` 里 `AutoDisableCorruptPlugins` 的值；
4. `stelarith-sync.json` 的完整内容（**把 `VoiceHubKey` 抹掉再发**）；
5. 「这个问题是升级后才出现的吗？之前的版本号是多少？」

第 5 条尤其有用 —— 配合 `05-升级降级与回滚.md` 的回滚机制，
通常能在答复之前先把教室恢复可用。
