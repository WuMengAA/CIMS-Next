# 04 · 多设备管理与远程运维

> 面向：电教委员 / 管理员。
> 核心问题：一个班一台不够，**几十台怎么管**，以及**人不在教室时怎么处理**。

---

## 1. 面板里的设备视图：先解决「看得见」

集控面板（`/admin/console`）里跟设备有关的有四个视图：

| 视图 | 看什么 | 需要权限 |
|---|---|---|
| **设备状态** | 每台设备在线/离线、最后心跳、IP、插件版本、所属班级 | 设备控制 |
| **ClassIsland 专页** | 单台设备下钻：模块开关、插件清单、切班、快捷操作 | 设备控制 |
| **远程控制** | 发起远程会话（见第 4 节） | 远程控制 |
| **权限与分级** | 当前账号到底能做什么（纯读） | 无 |

### 1.1 「从未上报」和「掉线」是两件事

面板区分这两个状态，别把它们混为一谈 —— 混了会让「端点配错了」和「教室断电了」
看起来一模一样，排查时完全没有方向：

| 面板显示 | 含义 | 该去查什么 |
|---|---|---|
| `reported = false` | **从未**上报过 | 插件没装好 / 地址填错 / 网络不通 —— 是**部署问题** |
| `reported = true, online = false` | 上报过，现在掉线 | 教室电脑关机了 / 网线掉了 —— 是**现场问题** |

### 1.2 判定在线的依据

**只用心跳时间差**，不做额外的连接探测。
理由很实际：教室里更常见的是「网络通但插件已死」，
主动探测会得出「在线」的错误结论，而心跳时间不会说谎。

## 2. 八个可远程开关的模块

面板上能对**每台设备**逐个开关以下模块（这就是「多设备操作」的粒度）：

| 模块 | 中文 | 核心 | 关掉会怎样 |
|---|---|---|---|
| `heartbeat` | 状态心跳上报 | ★ | **这台设备从面板上消失** |
| `command_poll` | 集控指令通道 | ★ | **失去远程控制能力** |
| `sync` | 资源主动同步 | | 不再拉课表/作息/科目 |
| `writeback` | 写回 ClassIsland 档案 | | 拉到了也不写进去，大屏不更新 |
| `notification` | 集控播报 | | 广播不再落成大屏播报 |
| `os_actions` | 本机动作（锁屏/截图） | | 集控不能再锁屏/截屏 |
| `remote_control` | 远程控制转发 | | 集控不能再发起 VNC 会话 |
| `message_feed` | 岛内消息中心 | | 教室端看不到最近的广播记录 |

**两个核心模块关不掉**（按钮置灰，事件层也兜底）。原因很直白：
关掉 `heartbeat`，这台设备就从面板视野里消失了，你再也无法远程把它打开 ——
变成必须走到教室去。这类「自我断线」的开关不应该存在。

`sync` / `writeback` 是两个**分开**的开关，这是有意的：
可以「同步但不写回」（用来先观察服务端下发的课表对不对，再决定是否生效），
这在换课表、排障时非常有用。

## 3. 多设备批量操作的现状与建议

### 3.1 面板提供的能力

- **按班级组织**：设备与班级课表是两层映射，同一班级的多台设备共享一份课表
  （服务端有「班级资源集」概念，改一次全班生效）。
- **广播带范围**：发通知时可以选范围（本班 / 全校），全班或全校一次性触达。
- **切班**：可以远程把某台（或某个群组的）设备切到指定班级课表。
- **模块开关**：逐台生效，也适合「某台设备临时关掉播报」这类场景。

### 3.2 建议的运维规范（经验之谈，能省很多时间）

| 规范 | 为什么 |
|---|---|
| **设备标识用统一格式**，如 `class<班号>-<位置>`（`class201-front`、`class201-back`） | 面板列表按名字排序时天然按班级聚在一起；出问题报「201前门」比报 IP 快得多 |
| **留空 `ClientUid` 让脚本用计算机名** | 天然唯一，不会出现两台设备同名互相覆盖状态 |
| **全校统一插件版本** | 面板设备列表可直接看到每台版本；版本不一致时，「别人正常我不正常」永远查不出结论 |
| **统一广播来源名** | 教室大屏上显示的发出来源应该全校一致，见下 |
| **一台设备一个班** | 同一台设备被两个班抢绑定时，课表会在两版之间跳 |

### 3.3 广播来源名（教室大屏上显示的那个名字）

教室大屏收到广播时会显示「发出来源」。这个名字**可配置**，不用改代码：

改 `…\data\Plugins\StelarithControlPlugin\stelarith-sync.json` 的
`NotificationSourceName`（默认「集控广播」），重启 ClassIsland 生效。

建议全校统一成一个名字（例如「校园广播站」），并且在部署包里预设好 —— 
部署时改 `config\deployment.json` 的 `NotificationSourceName` 即可，装出来的每台都一致。

### 3.4 大屏 / 看板（另一条显示路径）

如果某个场景需要「浏览器全屏大屏」（而不是 ClassIsland 主界面），
仓库里有独立的一套 `ext/classisland-voicehub-display/bridge/`：一个零依赖 Node 桥，
把点歌数据落地成 JSON 并提供 `http://localhost:8787/board` 全屏页面。

它与插件是**互补关系**（插件管岛内组件，bridge 管浏览器大屏），不是替代。

## 4. 远程方案：人不在教室能做什么

按「需要装什么」分成两档。**这一档很重要：先看清单，再看能做什么。**

### 4.1 只需本部署包（无额外组件）

这些能力由集控插件本机执行，**不需要装任何代理程序**：

| 能力 | 说明 |
|---|---|
| 广播通知 | 发文字通知，教室大屏播放遮罩播报（可按本班/全校） |
| 切班 | 远程把设备切到另一个班的课表 |
| 锁屏 | 让教室电脑立刻锁屏 |
| 截图 | 抓取教室电脑当前屏幕 |
| 模块开关 | 远程开关上面那 8 个模块 |
| 状态查询 | 在线状态、插件版本、模块开关状态 |

对应面板的「设备状态」「ClassIsland 专页」「通知」视图。

### 4.2 由本地代理提供（本包**已含**，部署时自动安装）

`1-部署到本机.cmd` 会把本地代理（`agent\stelarith-agent.exe`）装到
`<安装目录>\agent\`，并注册随登录自启的计划任务 `Stelarith-Agent-AutoStart`。

| 能力 | 说明 |
|---|---|
| 远程桌面（VNC / noVNC 内嵌） | 代理接收 `POST /task` 拉起 VNC；面板经 noVNC 内嵌显示 |
| 系统级重启 | 真正的 `shutdown /r`（**不是**重启 ClassIsland 界面） |

它只监听 `127.0.0.1:17999`，不对外暴露；所有触发都来自本机插件的转发。
令牌的 message 形如 `action|ts`，并校验 `|now-ts| <= 60s` 防重放。

#### 用起来必须知道的三件事

1. **指令密钥要两边一致。**
   面板 → 设置 → **指令密钥**，必须与 `config\deployment.json` 里 `Agent.Secret` 完全一样。
   不一致 → 代理会拒绝指令（面板上会显示拒绝原因）。
   更安全的做法是改配 `Agent.SitePubKey`（Ed25519 公钥，网站持私钥签名），
   这样教室机上不放共享密钥，泄露了也伪造不出指令。

2. **远程桌面还需要本机装 VNC 服务。**
   代理只负责「按需拉起本机 VNC」，它不含 VNC 本体。机器上默认没装，
   此时远程控制会停在这一步并**返回明确错误**。
   装好后把启动命令填到 `Agent.VncCmd`（默认 `vncserver`）。

3. **代理随「登录」启动，不是随「开机」。**
   刻意如此：以 SYSTEM 跑在会话 0 的进程拉起的 VNC 拿不到交互桌面，看屏会是一片黑。
   这与 ClassIsland 一致 —— 机器没登录时它本来也不在跑。
   验证：跑 `2-环境自检.cmd`，看「本地代理 / 代理自启任务 / 代理指令验签」三项。

> **排障提示**：面板上「远程控制」点下去没反应时，先跑一次自检。
> 代理侧的任何拒绝（没装、没跑、密钥不符、VNC 拉不起来）都会显示成**具体原因**，
> 不会再出现「HTTP 200 但什么都没发生」这种无从下手的情况。

> **安全提醒**：远程控制是这套系统里权限最高、也最需要收紧的能力。
> 建议只给「远程控制」档位的人开启 `remote_control` 模块，其余设备保持关闭。

### 4.3 远程排障（不用走进教室的兜底办法）

教室里出问题、又不想跑一趟时，最快的路径是：

1. 让老师双击 `2-环境自检.cmd`；
2. 把整屏内容（或加 `-Report` 参数生成的 txt）发回来。

这份报告覆盖：系统版本、内存、分辨率、安装完整性、进程与启动时间、
插件版本、服务端连通性（TCP + Manifest + 面板端口）、插件日志最后几行。
**它已经能定位 90% 的现场问题**，比电话里来回问快得多。

## 5. 权限：两台正交的轴

集控面板的权限是**两个独立的维度**，不是一条高低线：

| 轴 | 取值 | 作用 |
|---|---|---|
| **等级轴** | L1 ~ L5 | 内容类操作的等级门槛 |
| **设备轴** | `watch` / `control` / `remote` / `manage` | 对设备能做什么 |

视图级也有门控（避免「点进去只有一片禁用按钮」）：

| 视图 | 要求 |
|---|---|
| 课表 / 配置 / 通知 / 设备状态 / ClassIsland | 设备控制 |
| 插件 | 设备管理 |
| 远程控制 | 远程控制 |
| 故障报告 / Bug | 上报 |
| 权限与分级 | 无（任何能进面板的人都该看得到自己能做什么） |

**权限的判断一律在服务端算，前端只负责渲染。**
前端自己推导权限，是最容易出现「界面显示能点、一点就 403」的地方。

「权限与分级」页会把四轴矩阵和**当前账号**的解算结果显示出来 ——
遇到「我为什么点不了这个按钮」，先看这一页。

## 6. 日常巡检清单

| 频率 | 检查 | 期望 |
|---|---|---|
| 每天 | 面板首页设备在线数 | 与在校班级数一致 |
| 每周 | 抽 1–2 台跑自检 | 全绿 |
| 每周 | 面板设备列表的插件版本列 | 全校一致 |
| 每月 | 核对设备与班级绑定关系 | 没有「孤儿设备」 |
| 换教室/搬设备后 | 重跑一次部署脚本（重写身份） | 新 `ClientUid` 不与旧设备冲突 |
