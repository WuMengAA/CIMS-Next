# 05 · 升级、降级与回滚

> 面向：电教委员 / 运维。
> 一句话原则：**换 DLL 之前必须先停 ClassIsland**，因为宿主会锁住 DLL。
> 脚本已经帮你处理了顺序，但理解这一点能救你于 `Device or resource busy` 的困惑。

---

## 1. 先看清要升级的是什么

本系统里有两个东西会各自升级，**它们是独立的**：

| 对象 | 版本号在哪看 | 怎么升 |
|---|---|---|
| **集控插件** | 面板设备列表 / 插件管理页（读 `manifest.yml` 的 `version`） | 换插件目录里的 4 个文件 |
| **ClassIsland 本体** | 应用目录名 `app-<版本>` | 换整个 `app-<版本>` 目录 |

日常绝大多数升级**只需要换插件**（约 500 KB），不必动 281 MB 的本体。

---

## 2. 升级插件（最常见）

### 2.1 准备

拿到**新版本的部署包目录**（形态和首次部署那个一样，含 `app\` 与 `seed\data\`）。

### 2.2 执行

```cmd
3-升级或降级.cmd -From E:\ClassroomDeploy-20261001
```

脚本会：
1. 停止 ClassIsland（- 关键，否则 DLL 复制失败）；
2. 把当前插件文件备份到 `插件目录\.bak-<时间戳>\`；
3. 复制 `StelarithControlPlugin.dll` + `deps.json` + `pdb` + `manifest.yml`；
4. 重启 ClassIsland；
5. 检查是否出现**本轮新增**的插件日志，确认新代码真的跑起来了。

### 2.3 只升级插件时不要做的事

不要只把 DLL 手工 `cp` 过去。**`manifest.yml` 必须跟 DLL 一起换。**

原因：面板和插件管理页显示的版本号**读的是 `manifest.yml`**，不是程序集版本。
只换 DLL 的结果是「代码是新的，界面上版本号还是旧的」——
这个坑真实发生过，会导致你以为升级没成功而反复折腾。

> 另一个同类坑：`manifest.yml` 是 `.csproj` 的 `Content` 项，**只在构建时复制到输出目录**。
> 所以「改了 manifest 但没重新构建」= 构建产物里的 manifest 还是旧版本。

---

## 3. 升级 ClassIsland 本体

```cmd
3-升级或降级.cmd -From E:\ClassroomDeploy-20261001 -WithApp
```

脚本用 `robocopy` 复制本体，并**显式排除 `data` 目录** ——
课表、插件配置、日志都不会被动。

升级后可能出现多个 `app-*` 目录（旧版 + 新版），这本身没问题：
`ClassIsland.exe` 会按 `files.json` 选取要跑的目标版本。
但为了磁盘干净，确认新版可用后可以删掉旧目录。

### 如果教室电脑不能上外网

ClassIsland 自身有自动更新功能，它会去公网检查。**离线教室建议关掉自动更新**，
或者把它指向校内更新源（把官方更新包镜像到校内静态服务器，客户端改「更新通道」地址）。

这样做的好处：更新节奏由你控制，不会某天突然全班自动升级到未经你验证的版本。

---

## 4. 降级（回退到旧版本）

**降级和升级是同一个动作**，只是把 `-From` 指向**旧版本**的部署包：

```cmd
3-升级或降级.cmd -From E:\ClassroomDeploy-旧版本
```

不需要额外的「降级模式」，因为脚本只做「用给定来源覆盖当前」，
版本号高低对它没有意义。

前提：你手上得有那个旧版本的包。
**所以每次升级前，把用过的部署包留一份** —— 这是最简单的「回退保险」。

---

## 5. 回滚（回到上次替换前的状态）

### 5.1 列出所有备份

```cmd
4-回滚.cmd
```

会列出插件目录下所有 `.bak-*` 备份，并显示每个备份里的插件版本号。
输入编号即可恢复。

### 5.2 直接回滚到最近一次

```cmd
4-回滚.cmd -Last
```

### 5.3 指定某个备份

```cmd
4-回滚.cmd -FromBackup "C:\ClassIsland\data\Plugins\StelarithControlPlugin\.bak-20260916-101530"
```

### 5.4 只是同步配置错了

最轻量的一档：只把「服务端地址/租户/设备标识」恢复成部署包里的值。

```cmd
4-回滚.cmd -RestoreSyncOnly
```

适用场景：别人把 `stelarith-sync.json` 改乱了、或者想换回默认地址。

### 5.5 回滚也是安全的

回滚前脚本会先把**当前**状态再备份一份（`.bak-before-rollback-<时间戳>`），
所以「回滚错了想切回来」也是可以的。

---

## 6. 备份清单：什么被自动备份了，什么没有

| 文件 | 备份方式 | 在哪 |
|---|---|---|
| 插件 dll / deps / pdb / manifest | 每次升级或回滚前自动 | `插件目录\.bak-<时间戳>\` |
| `stelarith-sync.json` / `stelarith-panel.json` | 每次升级、回滚、部署前自动 | 同上，或 `*.before-deploy-<时间戳>` |
| 宿主 `Settings.json` | 部署脚本修改前自动 | `data\Settings.json.before-deploy-<时间戳>` |
| 课表档案 `Profiles\Default.json` | **不自动备份** | — |

课表档案不自动备份，是因为它由集控同步维护，「上一个版本」随时能从服务端重新下发。
但如果你的课表是**手工在本机编的**，请自己定期拷一份 `data\Profiles\` 出来。

## 7. 批量升级（多台设备）

### 7.1 U 盘逐台（最稳，推荐）

带上新版包，到每台机器上执行一次 `3-升级或降级.cmd -From <U盘路径>`。
一台约 1 分钟。

### 7.2 远程批量

前提：目标机开了 WinRM/SMB 且有管理员凭据。

```powershell
$targets = @('10.0.0.21','10.0.0.22','10.0.0.23')
$cred = Get-Credential
foreach ($t in $targets) {
    # 1) 送包
    robocopy "\\<源>\ClassroomDeploy-新" "\\$t\C$\ClassroomDeploy-新" /E /NFL /NDL /NJH
    # 2) 远程执行
    $s = New-PSSession -ComputerName $t -Credential $cred
    Invoke-Command -Session $s -ScriptBlock {
        powershell -ExecutionPolicy Bypass -File C:\ClassroomDeploy-新\scripts\upgrade.ps1 `
            -From C:\ClassroomDeploy-新
    }
    Remove-PSSession $s
}
```

### 7.3 批量升级后必须做的一致性检查

在面板的设备列表里确认：**所有设备显示同一个插件版本号**。

只要有一台没升上去，它的行为就会和其他设备不同，而这类差异在教室里表现为
「别的班好好的，就我们班不行」，排查成本极高。

## 8. 判断「新版本真的生效了」的硬办法

不要凭感觉，用这两个客观判据：

### 判据 1 · 比对进程启动时间与 DLL 修改时间

如果**进程启动时间早于 DLL 修改时间**，说明正在跑的是旧代码。
（这个坑真实发生过：改了代码、DLL 也换了，但进程从早就在跑，一直加载着内存里的旧版本。）

`2-环境自检.cmd` 里已经把这一条做成了检查项。

### 判据 2 · 看是否出现「本轮新增」的日志文件

`app-<版本>\` 目录下的 `ste-*.log` 是插件各守护线程写的。
新代码路径启动时会创建**新的**日志文件。升级脚本正是用这个来确认生效的。

### 另外：面板里的版本号

面板读的是 `manifest.yml` 的 `version`，所以版本号变了就说明 manifest 换成功了 ——
但它**不能**证明 DLL 也换了。两个判据要一起看。

---

## 9. 出问题时的处理顺序

```
升级后教室端行为异常
  ├─ 1) 跑 2-环境自检.cmd         → 先看有没有明确的红项
  ├─ 2) 4-回滚.cmd -Last          → 一分钟内退回上一个可用版本
  ├─ 3) 还有问题 → 4-回滚.cmd -RestoreSyncOnly  → 排查是不是配置被改乱
  └─ 4) 都不行 → 把自检报告发给服务端管理员
```

**先回滚、再分析，不要在现场边猜边改。**
教室里有人在等着上课，恢复可用性的优先级高于找出根因。
