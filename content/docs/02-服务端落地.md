> 面向：服务端管理员 / 运维。
> 结论先行：**教室端只需要能访问两个地址** —— CIMS 的 8096 和 面板的 8090。
> 服务端放哪里不重要，重要的是这两个地址从教室网络里能通。

---

## 1. 先把「网址」定下来

整套系统对外一共只有 **两个** 地址需要记住。教室端的配置里也只填这两个。

| 名称 | 用途 | 形态 | 例子 |
|---|---|---|---|
| **CIMS 地址** | 教室端拉课表/收广播/上报状态 | `http://<主机>:8096` | `http://10.0.0.10:8096` |
| **面板地址** | 电教委员/管理员用浏览器打开 | `http://<主机>:8090/admin/console` | `http://10.0.0.10:8090/admin/console` |

### 关于 CIMS 地址的一个重要提醒

**地址里的主机名只用来「找到机器」，租户身份完全由插件配置的 `Slug` + `BaseDomain` 决定。**

CIMS 靠请求里的 `Host` 头识别租户，而教室端插件会把这个头**主动覆写**成 `<slug>.<基域>`
（联网时例：`demo-class.localhost`），与它实际连的地址无关。服务端则要求这个 Host
**必须以 `.BaseDomain` 结尾**，否则解析不出租户 → 403。

于是「该填 IP 还是域名」的答案，取决于服务端的 `CIMS_BASE_DOMAIN`：

| 服务端 `CIMS_BASE_DOMAIN` | 插件 `BaseDomain` | CIMS 地址该填 | 说明 |
|---|---|---|---|
| `localhost`（内网/开发） | `localhost` | `http://10.0.0.10:8096` | **填 IP**。此时填域名反而 403 —— 因为插件覆写的 Host 是 `demo-class.localhost`，服务端只按 `.localhost` 解析，你写的域名不参与 |
| `cims.example.com`（公网） | `cims.example.com` | `https://demo-class.cims.example.com` | **填域名**。建议直接用租户自己的子域名，这样插件连接的目标与它覆写的 Host 完全一致 |

**一句话：两边必须对上。**对不上的表现是清一色的 403（`code=100403 未识别出租户`）。

> 公网部署（泛域名 + Cloudflare Tunnel + 双实例容灾）的完整步骤见
> **`docs/07-公网接入与容灾双实例.md`**。

### 面板地址则相反

面板是普通 Web 应用，用浏览器直接访问，**可以**用 IP、可以用域名、也可以走 HTTPS 域名。
它服务端在 8090 上再把请求转发到 CIMS 的管理端口 8097，中间没有 Host 覆写问题。

## 2. 服务端放在哪：三种选择

### 选择 1 · 校内一台常开机器（推荐）

一台校内服务器 / 教师机 / 电教办公室的电脑，长期开机。
优点：局域网延迟低、不依赖外网、数据在校内。
要求：**这台机器必须能被所有教室电脑访问到**（同网段或可路由）。

### 选择 2 · 就装在某一间教室的电脑上

如果只有一两个班要用，直接把服务端和教室端装在同一台机器上：

- 服务端地址填 `http://127.0.0.1:8096`；
- 其他班的电脑则填这台机器的局域网 IP。

代价：这台机器一关，全班（及其他班）都失去集控。
**只能作为过渡方案。**

### 选择 3 · 公网云主机

只有当教室能上外网、且愿意把课表数据放到公网时才用。
若走公网，务必注意：

- CIMS 的租户机制让它**不适合直接暴露**在公网域名下（见上文）。
- 推荐做法是前面加一层 Nginx 反向代理，把 Host 改写成 `<slug>.<基域>` 再转给 8096：

```nginx
# 公网入口 -> 本地 CIMS 客户端端口
server {
    listen 443 ssl;
    server_name cims.school.edu;

    location / {
        proxy_pass http://127.0.0.1:8096;
        # 关键：把 Host 改写成租户形式，否则 TenantMiddleware 会 403
        proxy_set_header Host demo-class.localhost;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 120s;
    }
}
```

> 反代改写 Host 这一招，同时也是让 **ClassIsland 官方集控** 能对接 CIMS 的唯一办法
> （官方客户端不会自己设置 Host 头）。详见 `03-官方集控与绑定设置.md`。

## 3. 服务端组件与端口清单

| 端口 | 组件 | 谁需要访问 | 是否必须对外开放 |
|---|---|---|---|
| **8096** | CIMS 客户端 API | **所有教室端** | ★必须 |
| **8090** | 网站 / 集控面板 | 电教委员、管理员（浏览器） | ★必须（给人用） |
| 8097 | CIMS 管理端 API | 网站服务端（本机回环即可） | 不需要 |
| 8098 | CIMS 管理端（备用/后台） | 本机维护 | 不需要 |
| 8100 | gRPC | 仅在启用官方集控服务器模式时需要 | 视方案而定 |
| 5432 | PostgreSQL | CIMS（本机） | 不需要 |
| 6379 | Redis | CIMS（本机） | 不需要 |

**只需要在防火墙放行 8096 和 8090。** 其余推荐只监听回环。

### 放行命令（管理员 PowerShell）

```powershell
foreach ($p in 8096, 8090) {
    New-NetFirewallRule -DisplayName "Stelarith Server (TCP $p)" `
        -Direction Inbound -Action Allow -Protocol TCP -LocalPort $p -Profile Any
}
```

> 部署包的 `deploy.ps1` 带 `-OpenFirewall` 参数可以自动放行 8090/8096/8097/8098，
> 但只应在「这台机器就是服务端」时使用；纯教室端不需要任何入站放行。

### 验证方法

在**另一台**机器上执行（不要在本机测，本机测不出防火墙问题）：

```powershell
Test-NetConnection -ComputerName 10.0.0.10 -Port 8096
Test-NetConnection -ComputerName 10.0.0.10 -Port 8090
```

两项都 `TcpTestSucceeded : True` 才算通。

## 4. 服务端部署顺序

CIMS 是 FastAPI + PostgreSQL + Redis；网站是 SvelteKit + Node。**有先后依赖**，顺序很重要。

### 4.1 依赖服务先起来

1. **PostgreSQL**（5432）。CIMS 启动时会连库并建表，库不可用会直接起不来。
2. **Redis**（6379，Windows 上通常是 Memurai）。用于缓存/限流。

### 4.2 再起 CIMS

```powershell
cd <CIMS-backend>
.\.venv\Scripts\python.exe cims-boot.py
```

起不来的常见原因，按出现频率排：

| 现象 | 原因 | 处理 |
|---|---|---|
| 导入期报 `ImportError` | 新加的模型没在 `models/database.py` 里导出 | 补导出（漏导出会在建表前就炸，整个后端起不来） |
| 建表后接口 500 | `search_path` 被切回 `public` | 不要动 schema 上下文，脏 ORM 对象会在 commit 时才 flush 到 public 的同名旧表 |
| 端口起了但请求 403 | 缺 `Host: <slug>.<基域>` | 正常现象，用带 Host 头的请求验证 |

**启动成功的判据**：8096 / 8097 / 8098（或 8100）四个端口都在监听。

### 4.3 最后起网站

```powershell
node -r <path>\loadenv.cjs build\index.js
```

> `-r loadenv.cjs` **不能省**。SvelteKit 的 adapter-node 在动态私密环境变量的快照点会
> 直接读 `process.env`，没有这个加载器，`CIMS_MANAGEMENT_URL` 之类的变量在运行时是空的，
> 表现为面板「连不上 CIMS」。

**启动成功的判据**：`http://127.0.0.1:8090/admin/console` 返回 200。

### 4.4 开机自启

用 Windows 计划任务，触发器选「计算机启动时」，运行账户选 SYSTEM，并勾选
「不管用户是否登录都要运行」+「如果任务失败，每隔 X 分钟重启」。

三个任务：

| 任务名 | 启动什么 | 注意 |
|---|---|---|
| `CIMS-Backend-AutoStart` | `start-cims.ps1` → `cims-boot.py` | 启动脚本里要先等待 5432/6379 就绪（否则会抢跑失败） |
| `StelarithServer` | `run-prod.bat` → node 8090 | `run-prod.bat` 内部自带重启循环；注意端口占用时先清掉残留监听 |
| PostgreSQL / Redis | 各自的系统服务 | 设为自动启动 |

排查「任务触发了但服务没起来」：先看 `LastTaskResult`。
`255` 且日志一行都没有 —— 通常是 `.bat` 里有 cmd 语法错误（例如 `echo` 后出现裸 `|`），
cmd 在解析阶段就崩了，根本执行不到写日志那一步。

### 4.5 启动脚本里的凭据

**不要把密码写进启动脚本。** 项目里发生过一次明文凭据随公开仓库泄漏的事故。

正确做法：凭据放**未入库**的 `.env`，由 `loadenv.cjs` 在启动时注入。
`loadenv.cjs` 的语义是「只填空值」，所以：

- 启动脚本里 `set` 的变量会**覆盖** `.env`；
- 反过来，启动脚本里写死了凭据，就会**静默屏蔽** `.env` —— 看起来配置改了却没生效，
  排查起来非常费时间。

## 5. 降级措施（服务端不可用时会怎样）

这是设计里特意做过的功课。**任何一环出问题，教室里都不能黑屏。**

### 5.1 服务端完全不可达（最常见：网线掉了 / 服务器关机）

| 受影响 | 表现 | 恢复 |
|---|---|---|
| 课表更新 | 教室端继续用**上一次同步成功的档案**显示，上课提醒照常响 | 网络恢复后自动继续同步 |
| 集控广播 | 收不到新广播 | 同上 |
| 点歌上屏 | 组件停留在最后一次数据 | 同上 |
| 设备状态上报 | 面板上这台设备显示为**离线**（按最后心跳时间判定） | 同上 |

关键点：**上课提醒、课表显示这些核心功能完全在本地，不依赖服务端。**
断网不会影响正常教学。

### 5.2 插件同步失败

插件是「拉取式」的，失败只是这一轮没拉到，**不会退出、不会禁用**。
下一轮继续试。所有细节写在应用目录的 `ste-*.log` 里，用 `2-环境自检.cmd` 看最近几行。

### 5.3 插件自身抛异常

`Settings.json` 的 `AutoDisableCorruptPlugins` 已被强制设为 `false`。
否则「别的插件抽风 → 集控插件被连带自动禁用 → 教室端静默失联且无告警」是真实会发生的。

### 5.4 服务端整体迁移（换机器 / 换 IP）

教室端只改**一个文件**：`…\data\Plugins\StelarithControlPlugin\stelarith-sync.json`
里的 `ClientAppBase`。改完重启 ClassIsland 即可；或者重新跑一次 `deploy.ps1`
（它会重写这个文件并自动备份旧的）。

如果只是**换 IP、同网段**，也可以给服务端配固定 IP 或 DHCP 保留，避免逐台去改。

### 5.5 想要「双服务端」兜底

目前**不支持**自动故障切换。可行的做法：

- 服务端用固定 IP（或内网 DNS 别名），迁移时改 IP 指向新机器，教室端不用动；
- 或者准备一份「备用地址」，出故障时用 `4-回滚.cmd -RestoreSyncOnly` 配合修改后的
  `config\deployment.json` 批量切换（走 U 盘或远程执行）。

> 有意不做自动切换：两套服务端的课表版本号独立演进，自动切换会导致
> 档案在两个版本之间来回跳。宁可明确地手动切。

## 6. 服务端日常运维清单

| 频率 | 做什么 | 命令 / 位置 |
|---|---|---|
| 每天 | 看一眼面板首页设备在线数 | `/admin/console` |
| 每周 | 检查三个计划任务的状态与上次结果 | `Get-ScheduledTask` / 任务计划程序 |
| 每周 | 抽查一台教室机的自检报告 | 让老师跑 `2-环境自检.cmd -Report check.txt` |
| 每月 | 备份数据库 | `pg_dump`（见下） |
| 换课表时 | 在面板里改，不要直接改库 | `/admin/console` |
| 有新版插件 | 按 `05-升级降级与回滚.md` 逐台或批量升级 | — |

```powershell
# 数据库备份（每月，或每次大改课表前）
& "C:\Program Files\PostgreSQL\16\bin\pg_dump.exe" -U postgresql -d cims -f "D:\backup\cims-$(Get-Date -Format yyyyMMdd).sql"
```
