用了一段时间之后你会需要知道两件事：**花了多少钱、还能用多久。**

## 去哪里看用量

DeepSeek 的用量可以在控制台看。登录 `platform.deepseek.com`，在用量或账单页面可以看到每天的调用次数和 token 消耗。商汤日日新可以在 `platform.sensenova.cn` 的控制台查看剩余免费额度。

> [!TIP]
> 建议**开发期就养成看用量的习惯**，别等账单来了才发现。特别是写循环调用、批处理脚本的时候，一个没加限制的 `for` 循环能在几分钟内烧掉你想象不到的量。

## 控制 token 消耗

说穿了就是**少发废话**。每次问问题之前想清楚自己要什么，把问题写清楚再发。

不要发一条"你好"，等它回了再发"我想问个问题"，再等它回了再发真正的问题——这样你会为前面那些废话付三次 token 的钱。**直接把完整问题一次发过去。**

几个真正有效的省钱手段：

| 手段 | 做法 | 效果 |
|------|------|------|
| 一次问完整 | 约束、上下文、格式一次说清 | 减少往返轮次 |
| 控制历史长度 | 长对话只保留最近几轮 + 早期摘要 | 直接砍掉大头输入 |
| 限制输出长度 | 设 `max_tokens` | 防止意外超长输出 |
| 用小模型做小任务 | 分类、抽取这种活不用最强模型 | 单价差很多 |
| 缓存重复结果 | 相同输入直接复用 | 完全省掉 |

## 本地模型和 API 怎么配合

我的经验是：**简单重复的任务给本地模型，复杂推理和需要最新知识的任务给 API。**

| | 本地模型 | API |
|---|----------|-----|
| 成本 | 不要钱（电费除外） | 按 token 付费 |
| 隐私 | 数据不出本机 | 数据要发给服务商 |
| 能力 | 有限，适合格式化、改错字、简单文本处理 | 强，适合复杂推理 |
| 知识 | 受训练截止限制 | 相对更新 |

两者配合用，能把成本压到最低。

## 遇到错误先看状态码

| 状态码 | 含义 | 怎么办 |
|--------|------|--------|
| `400` | 请求体格式不对 | 检查 JSON 是否合法、字段是否拼错 |
| `401` | API Key 无效或过期 | 检查 Key 有没有抄全 |
| `403` | 没有权限 | 检查账号状态与模型权限 |
| `404` | base URL 或模型名写错 | 核对地址与模型名 |
| `429` | 调用频率超限 | 退避后重试 |
| `500` / `502` / `503` | 服务端问题 | 等一会儿再试，看官方公告是否维护 |

规律很简单：**4开头基本是你这边的问题，5开头是服务端的问题。** 大部分时候你遇到的都是 4 开头的错误，耐心看看错误信息，问题通常就在里面。

> [!NOTE]
> 对 `429` 和 5xx 这类**临时性**失败，正确做法是**指数退避重试**（等 1s、2s、4s…），而不是立刻重发。立刻重发只会让你更快触发限流。

## 关键词汇解释

| 术语 | 解释 |
|------|------|
| **控制台/Console** | 平台的后台管理界面。DeepSeek在 `platform.deepseek.com`，商汤在 `platform.sensenova.cn`。 |
| **用量统计** | 控制台里可以看到每天/每月的调用次数和token消耗。 |
| **本地模型** | 跑在自己电脑上的模型，不需要联网调用API。用Ollama、LM Studio等工具运行。优点是免费、隐私安全，缺点是能力比云端大模型弱。 |
| **状态码** | HTTP响应的状态码。2xx表示成功，4xx表示客户端错误，5xx表示服务端错误。 |
| **401 Unauthorized** | API Key无效或已过期。检查Key是否正确。 |
| **429 Too Many Requests** | 调用频率超限，退避后重试。 |
| **500 Internal Server Error** | 服务端内部错误，通常是平台临时问题，等会儿再试。 |
| **指数退避** | 重试间隔按倍数增长（1s→2s→4s…），避免失败时把请求打得更密。 |
