> 这一份回答两个问题：
> ① ClassIsland **官方**的集控功能是什么、怎么绑定？
> ② 它和我们这套 **星璃集控（CIMS + 自研插件）** 是什么关系、该怎么选？

---

## 1. 先分清两套「集控」，它们不是一回事

| | **ClassIsland 官方集控** | **星璃集控（本项目）** |
|---|---|---|
| 谁做的 | ClassIsland 官方内置 | 本项目自研（CIMS 服务端 + CIMS 插件） |
| 怎么开 | 设置 → 集控 → 加入集控 | 装插件，填 `stelarith-sync.json` |
| 下发什么 | 课表 / 作息 / 科目 / 组件 / 默认设置 / **策略** / **凭据** | 同一套 7 类资源 + 广播通知 + 点歌上屏 |
| 上行什么 | 无（纯下行） | **设备遥测**（在线状态/版本/模块开关/插件清单） |
| 命令通道 | 集控服务器模式下走 gRPC | 走 HTTP 轮询命令队列 |
| 权限保护 | **有**（禁用改设置、禁改课表、禁退出、凭据校验） | 无（依赖宿主的权限体系） |
| 服务端状态 | 静态配置模式**可用**；集控服务器模式官方标注「🚧正在开发」 | 已可用 |

**两者用的是同一套数据格式。** 这不是巧合：CIMS 的 Manifest 端点产出的结构，
与官方 `ManagementManifest` 是同构的（同样是 7 个 `{Value, Version}` 源 + `ServerKind` + `OrganizationName`）。

实测比对（CIMS 的 `/api/v1/client/{uid}/manifest` 返回）：

```json
{
  "ClassPlanSource":       { "Value": "http://…/api/v1/client/ClassPlan?name=cp_class02", "Version": 1757… },
  "TimeLayoutSource":      { "Value": "…/TimeLayout?name=tl_school",  "Version": 1757… },
  "SubjectsSource":        { "Value": "…/Subjects?name=sub_school",   "Version": 1757… },
  "DefaultSettingsSource": { "Value": "…/DefaultSettings?name=default","Version": 1757… },
  "PolicySource":          { "Value": "…/Policy?name=default",        "Version": 1757… },
  "ComponentsSource":      { "Value": "…/Components?name=default",    "Version": 1757… },
  "CredentialSource":      { "Value": "…/Credentials?name=default",   "Version": 1757… },
  "ServerKind": 1,
  "OrganizationName": "CIMS Server",
  "CoreVersion": "2.0.0.0"
}
```

这正是官方 `ManagementManifest` 的形状。所以**理论上可以让官方客户端直接对接 CIMS** ——
但有一个硬前提，见第 4 节。

## 2. 官方集控的两个模式

官方支持两种部署方式（字段名 `ManagementServerKind`）：

| 值 | 名称 | 官方状态 | 需要什么 |
|---|---|---|---|
| **0** | 静态托管的配置文件 | ✅ 可用 | 一个能返回 `manifest.json` 的静态地址 |
| 1 | 集控服务器 | 🚧 官方标注「正在开发」 | 实现 CMSP（Cyrene 管理服务协议）的 gRPC 服务端 |

### 模式 0 的工作原理

1. 客户端按 `ManifestUrlTemplate` 拉取 `manifest.json`（清单，含 7 个源的 URL 与版本号）；
2. 按需拉取各源文件，并**缓存在本地**；
3. 此后只有版本号变化时才重新拉 —— 所以静态托管也能做到「改一次、全班更新」，
   前提是**清单里的 `Version` 必须递增**（官方文档明确提醒：改了 ReVersionString 却不升版本号，客户端不会更新）；
4. 一旦启用集控，客户端将**强制加载「管理档案」**，它与普通档案**数据不互通**
   （也就是说：本地手改的课表不会与管理档案合并）。

## 3. 绑定设置：字段与写法（官方规范，逐条核对过）

### 3.1 绑定文件

文件名固定为 **`ManagementPreset.json`**，放在 **ClassIsland 安装目录**（与 `ClassIsland.exe` 同级）。

```json
{
  "ManagementServerKind": 0,
  "ManagementServer": "",
  "ManifestUrlTemplate": "https://example.com/manifest.json",
  "ClassIdentity": "1-201"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `ManagementServerKind` | int | 是 | `0` = 静态配置文件；`1` = 集控服务器 |
| `ManagementServer` | string | **仅 Kind=1 时必填** | 集控服务器地址，如 `https://example.com:23333` |
| `ManifestUrlTemplate` | string | **仅 Kind=0 时必填** | 集控清单 URL 模板 |
| `ClassIdentity` | string | 否 | 班级标识符，例如 `1-201`（初一一班 → 1-201 这类命名） |

### 3.2 URL 模板的占位符 —— 只有两个

官方明确支持以下替换（请求时直接替换成字面量）：

| 模板 | 替换为 |
|---|---|
| `{id}` | 客户端的 ID（用于按班级/设备区分） |
| `{cuid}` | 客户端的**唯一**客户端 ID（CUID，GUID 形式） |

示例：

```
https://example.com/client/{id}/manifest.json
  -> https://example.com/client/TEST_ID/manifest.json

https://example.com/client/{cuid}/manifest.json
  -> https://example.com/client/9f5ab079-83c7-aeba-db2f-db39a0009845/manifest.json
```

> **注意**：模板替换只作用于 `ManifestUrlTemplate` 本身。清单里各源的 URL 是
> 客户端**直接照用**的，不会二次替换占位符。所以要给每个班/每台设备不同的资源，
> 就得让「清单 URL」带占位符，由返回的清单去指向不同的资源文件。

### 3.3 界面上的绑定项

ClassIsland 里有专门的三页设置（实测 2.1.0.1 存在）：

- **设置 → 集控**：启用管理功能、看当前归属、点「加入集控」；
- **设置 → 集控 → 凭据**：设 User / Admin 凭据与各操作的授权等级；
- **设置 → 集控 → 策略**：开关各项限制。

界面上会显示两个身份值，这两个值很关键：

| 界面显示 | 含义 | 在本项目里的对应 |
|---|---|---|
| **CUID** | 客户端**唯一** ID（GUID，自动生成，由宿主维护） | 与 CIMS 的 `ClientUid` 是**两套**东西（见 4.3） |
| **ID** | 你在设置里填的 `ClassIdentity` | 与 CIMS 的「班级标识」概念一致 |

此外还有「您目前正在受 *组织名* 管理」的提示，组织名来自清单里的 `OrganizationName`。

### 3.4 策略与凭据能做什么（这是官方集控最实用的部分）

**策略（Policy，9 项开关）**：

| 字段 | 效果 |
|---|---|
| `DisableProfileEditing` | 禁止编辑整个档案 |
| `DisableProfileClassPlanEditing` | 禁止编辑课表 |
| `DisableProfileTimeLayoutEditing` | 禁止编辑时间表 |
| `DisableProfileSubjectsEditing` | 禁止编辑科目 |
| `DisableSettingsEditing` | 禁止改应用设置 |
| `DisableSplashCustomize` | 禁止自定义启动屏 |
| `DisableDebugMenu` | 禁止进调试菜单 |
| `DisableEasterEggs` | 关闭彩蛋 |
| `AllowExitManagement` | 是否允许退出管理 |

**凭据（Credentials）**：两把密码（`UserCredential` / `AdminCredential`），
外加 7 个操作的授权等级（编辑授权设置、编辑策略、退出管理、编辑档案、编辑设置、退出应用、调整课表），
每项可取「不需要 / 用户凭据 / 管理员凭据」。

> **这就是「防止学生乱点」的正解**，而且是官方内建、经过验证的实现。
> 比自研插件去做「防关闭」可靠得多 —— 我们自研那部分只能改
> `AutoDisableCorruptPlugins`，属于补丁性质。

实测本机（未启用集控）的对应文件位于 `data\Config\Management\`，
内含 `Credentials.json` 与 `Policy.json`，两者都是 `IsActive: false` 的空壳。

> 官方 wiki 里写的路径是 `AppData/Management/`，与 2.1.0.1 便携版的实测路径不同。
> **以 `data\Config\Management\` 为准**；迁移/备份时按实测路径找。

## 4. 与本项目 CIMS 的对接：结论与前提

### 4.1 结论

**官方集控（模式 0）对接 CIMS，技术上可行，但必须先解决 Host 头问题。**

原因（已实测）：

| 请求 | 结果 |
|---|---|
| 带 `Host: demo-class.localhost` 请求 CIMS | **200** |
| 不带自定义 Host（官方客户端的行为） | **403 未识别出租户** |

官方客户端拉清单时用的是配置里写的地址，**不会**替你设置 `<slug>.<基域>` 这个 Host 头。
而 CIMS 的 `TenantMiddleware` 见到 Host 不以 `<基域>` 结尾就直接 403。

### 4.2 解决办法：加一层反向代理改写 Host

在服务端加 Nginx（或任何能改写请求头的反代），把 Host 固定成租户形式：

```nginx
server {
    listen 8099;
    server_name _;
    location / {
        proxy_pass http://127.0.0.1:8096;
        proxy_set_header Host demo-class.localhost;   # ← 关键
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

然后教室端官方集控这样填：

```json
{
  "ManagementServerKind": 0,
  "ManifestUrlTemplate": "http://10.0.0.10:8099/api/v1/client/{id}/manifest",
  "ClassIdentity": "class201-pc"
}
```

`{id}` 会被替换成 `ClassIdentity` 的值，正好对上 CIMS 路径里的 `{client_uid}`。

> 注意：反代只负责让请求进得来。清单里返回的各源 URL 是 CIMS 用
> `request.url_for()` 生成的**绝对地址**，会带上服务端自己的主机与端口。
> 若反代端口与 8096 不同，要么让反代也监听 8096（换机器），
> 要么在 CIMS 侧支持指定外部基址。**这一点在真正启用官方集控前必须先验证**，
> 不要假设它能直接跑通。

### 4.3 一个必须搞清的区别：CUID ≠ ClientUid

| | 官方 CUID | CIMS ClientUid |
|---|---|---|
| 生成者 | ClassIsland 自己（GUID，持久化在宿主里） | 部署时人工指定，或自动取计算机名 |
| 表单 | `9f5ab079-83c7-aeba-db2f-db39a0009845` | `class201-pc` |
| 用途 | 官方 gRPC 注册 / 模板替换 | CIMS 拉资源的路径参数 |

所以如果要用官方集控的 `{id}` 对上 CIMS，**应该把 `ClassIdentity` 填成 CIMS 认识的 `ClientUid`**
（例如 `class201-pc`），而不要去用 CUID。

### 4.4 集控服务器模式（Kind=1）能对接吗？

**目前不能，也不建议现在尝试。** 三个理由：

1. 官方文档明确标注集控服务器「🚧正在开发」——**服务端尚未发布**；
2. 该模式走的是 CMSP（Cyrene 管理服务协议）gRPC，客户端注册时会带上
   ClientGuid / Class ID / MAC 地址并交换公钥。CIMS 在 8100 上有 gRPC 端口，
   但**尚未验证它实现了 CMSP**（本项目自己的命令通道走的是 HTTP 轮询，不是 CMSP）；
3. 一旦对接错，客户端会卡在「已加入集控但连不上服务器」的状态，教室里很难现场恢复。

**结论：等官方发布集控服务器，或继续用本项目的 HTTP 通道。**

## 5. 两套机制并存时的冲突：档案双写

这是**最容易踩、也最难排查**的一个坑。

启用官方集控后，**官方客户端也会往宿主的课表档案里写**；
而星璃插件在 `ResourceWriteBack = true` 时**也会写**。
两边都写同一个档案，结果就是课表在两个版本之间来回跳，
或者一边写的被另一边覆盖，表现为「课表偶尔变回旧的」。

**规则：二选一。**

| 你的选择 | 怎么配 |
|---|---|
| 用星璃插件下发课表 | `stelarith-sync.json` 的 `ResourceWriteBack` = `true`（默认）；**不要**启用官方集控 |
| 用官方集控下发课表 | 启用官方集控；把 `ResourceWriteBack` 改成 `false`（部署时把 `config\deployment.json` 的对应项设为 `false`） |

即使关掉写回，**星璃插件仍然可以照常工作**（上报设备状态、收广播、点歌上屏）——
它只是不再碰课表档案。这是推荐的组合方式。

## 6. 决策表：什么情况用哪个

| 场景 | 推荐 |
|---|---|
| 只想统一课表 + 防学生乱动设置，不需要看设备状态/广播/点歌 | **官方集控（模式 0）** 就够了，甚至不需要 CIMS |
| 要设备在线状态、要广播通知、要点歌上屏、要远程操作 | **星璃插件（CIMS）** |
| 既要防乱动，又要集控广播 | **官方集控做课表+策略**，同时装星璃插件但 **关掉 `ResourceWriteBack`** |
| 教室端完全没有服务端（单机） | 官方集控（模式 0，托管在任意静态空间），或干脆只用本地档案 |
| 要远程控制（锁屏/重启/切班） | 必须用星璃插件（官方集控在当前版本没有可用的命令通道） |
