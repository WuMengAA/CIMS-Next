## 它是什么

星璃知识库是 Stelarith 平台里的**文档板块**，定位成可协同、可纠错的活知识库。任何读者发现错漏都能提交纠正建议，管理员审核后合并——文档因此持续生长，而不是一次性写完就陈旧。

> [!NOTE]
> 普通文档的宿命是"写完即开始过时"。把纠错入口开放给读者，是让它活得久一点的唯一办法。

## 猫娘 AI 助手「星璃」

知识库里住着一个角色化的 AI 助手「星璃」：负责导览、答疑、把零散文档串成路径。她不是通用聊天机器人，而是**绑定在本站内容上的向导**——你问"怎么接 RSS"，她会指向对应的笔记而不是泛泛而谈。

> [!NOTE]
> 星璃是虚构世界观里的原创角色（深紫渐变发色、琥珀色眼睛的猫娘），作为品牌的"人格化入口"，让冷冰冰的文档多一层陪伴感。

这个设计解决的是一个真实问题：文档站最大的流失点不是"没有内容"，而是**读者找不到内容**。一个绑定内容的向导，比一个通用搜索框更能把人留住。

## 协同纠错是怎么运转的

1. 读者在文档页点「纠错」，提交修改建议（diff 形式）
2. 建议进入后台「文档纠错」队列
3. 管理员审核、采纳或退回
4. 采纳即生成新版本，旧版本进归档可回滚

这条链路让"群众纠错"有去处，也保留了每次改动的痕迹。**审核环节不能省**——开放编辑而不审核，知识库会很快变成涂鸦墙。

## 与平台其他板块的关系

文档与博客、项目同属平台的内容层，复用同一套 frontmatter、渲染与权限机制，因此纠错、归档、RSS 能力天然贯通。

```
content/
├── posts/      博客 —— 记录过程（时效性强，个人视角）
├── projects/   项目 —— 说明产出（相对稳定，介绍性）
└── docs/       文档 —— 沉淀方法（长期维护，教程性）  ← 知识库
        └── 共享：frontmatter / 渲染管线 / 权限 / 归档 / RSS
```

三者共享底座但定位不同。分开是为了让每类内容有自己的更新节奏——**不该让教程跟着文章的时效一起腐烂**。

## 技术要点

| 能力 | 实现 |
|------|------|
| 内容存储 | 文件式（Markdown + frontmatter），无需数据库即可运行 |
| 版本 | 每次保存追加版本快照，支持一键回滚 |
| 权限 | 复用平台权限矩阵（admin / editor / moderator / user） |
| 渲染 | 与博客共用 Markdown 管线（表格、callout、代码高亮、KaTeX） |
| 纠错 | diff 建议 → 后台队列 → 审核合并 |

## 当前状态

知识库骨架与纠错链路已就绪，内容持续填充中。AI 导览「星璃」目前以内容检索为主，后续计划增强到"学习路径推荐"——不只是找到一篇文档，而是给出一条从入门到上手的路。
