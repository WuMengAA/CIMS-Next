# ClassIsland 内网更新源搭建

让全校客户端的 ClassIsland 自动更新走**校内更新源**，不依赖公网 GitHub，符合校园合规与带宽管控。

## 原理

ClassIsland 内置更新器，支持自定义更新通道（Update Channel / 更新源 URL）。把官方更新包镜像到校内静态服务器，客户端指向该 URL 即可自动检查并升级。

## 步骤

### 1. 准备静态服务器（任选）

- **Nginx**（推荐，已在 deploy 体系内）：
  ```nginx
  server {
      listen 80;
      server_name update.example.edu;
      root /srv/classisland-update;
      autoindex on;
  }
  ```
- 或 `python -m http.server` 临时托管（仅测试）。

### 2. 镜像更新包

从 ClassIsland 官方 Release 下载更新包（含 `RELEASES`、`*.nupkg`、应用文件），放入 `/srv/classisland-update/` 并保持目录结构。

> 建议用定时任务（cron / GitHub Action 自托管 runner）增量同步官方 Release，避免手动维护。

### 3. 客户端配置

在每台设备的 ClassIsland 设置 → 更新 → 更新通道，填入：

```
http://update.example.edu/
```

保存后客户端自动检查更新；也可在 CIMS 下发 `RestartApp`/`update-data` 命令统一触发。

## 与集控联动

- **客户端本体更新**：走内网更新源（本说明）。
- **配置 / 内容更新**：走 CIMS Manifest 自动拉取（无需逐台改），见实施方案 §6。
- **批量升级**：CIMS 对所有在线客户端批量下发更新指令（走 gRPC command；HTTP 入口见 CIMS management 端口 `/account/{acct}/client/{uid}/command/*`，或 `admin-frontend/GRPC_COMMAND_PROXY.md` 历史参考）。

## 注意

- 内网更新源需与客户端架构（x64 / arm64）匹配，建议同时镜像多架构包。
- 更新包版本号需单调递增，否则客户端不识别。
